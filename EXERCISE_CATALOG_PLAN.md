# План развития базы упражнений и ИИ-помощника

Статус: продуктовый план для последующей реализации. Дополняет [ТЗ по тренировкам и навигации](NAVIGATION_AND_WORKOUTS_SPEC.md), не заменяет его.

## Цель

Сделать каталог удобной личной базой: быстро находить упражнение, видеть прошлые результаты, добавлять его в программу, подбирать замену и хранить краткую памятку по технике.

Сохранить существующие каталог, историю и архитектуру приложения. Не создавать большую энциклопедию упражнений и не подключать внешнюю базу в первой версии.

## 1. Единый каталог с контекстным действием

| Точка входа | Действие при выборе |
|---|---|
| Профиль → Все упражнения | Открыть страницу упражнения |
| Тренировка → Добавить упражнение | Добавить в шаблон тренировки |
| Пункт программы → Добавить альтернативу | Сохранить альтернативу для пункта; при активном занятии сразу выбрать её |

В режиме выбора показывать назначение: «Добавить в тренировку B» или «Альтернатива для жима лёжа».

Каталожное упражнение имеет один устойчивый ID. История, заметки и техника общие для всех тренировок. Связь альтернативы хранится в конкретном пункте программы.

## 2. Поиск и список

- На первом экране сразу показывать упражнения и поиск, без обязательного перехода через группу мышц.
- Быстрые фильтры: «Все», «Избранное», «В программе».
- Дополнительные фильтры: основная группа мышц и оборудование.
- Без запроса: сначала избранные, затем остальные ранее выполнявшиеся по дате последнего выполнения, затем остальные по алфавиту; без повторов.
- С запросом: точное совпадение названия выше частичного. Искать также по другим названиям упражнения; учитывать выбранные фильтры.
- В строке: название, группа мышц, оборудование, последний результат и дата, использование в программах.
- Последний результат вычислять тем же правилом выбора репрезентативного подхода, что и график. Если завершённых выполнений нет — «Ещё не выполнялось».

Пример:

> Жим гантелей на наклонной скамье ☆  
> Грудь · Гантели  
> Последний раз: 40 кг × 10 · 8 ноября  
> В программе: A, C

## 3. Данные упражнения

| Поле | Назначение |
|---|---|
| Название | Основное имя, обязательно |
| Основная группа мышц | Фильтрация, обязательно |
| Оборудование | Необязательно; штанга, гантели, блок, тренажёр, другое |
| Избранное | Быстрый доступ |
| Другие названия | Поисковые синонимы, например OHP / жим стоя |
| Моя заметка | Личные настройки: наклон скамьи, положение сиденья, хват |
| Техника | Отдельная сохранённая краткая памятка |

Не смешивать личную заметку и общую справку по технике. Личную заметку показывать рядом с вводом подходов.

Старые упражнения не требуют заполнения новых полей. Не угадывать оборудование и синонимы автоматически при миграции.

## 4. Создание и управление

- Из поиска доступно «Создать “[запрос]”».
- Предзаполнять название и выбранную группу мышц; остальные поля необязательны.
- Перед созданием показывать похожие существующие названия, чтобы снизить число дублей.
- В режиме добавления сохранение сразу добавляет упражнение в нужную тренировку или альтернативы.
- Создание из профиля только создаёт каталожную запись.
- Предусмотреть архивирование: упражнение скрывается из обычного выбора, но сохраняет историю и доступно через фильтр «Архивные». Его можно восстановить.
- Если упражнение используется в программе, не архивировать молча: показать места использования и предложить сначала убрать его из шаблонов.
- Полное удаление упражнения с историей в эту версию не входит.

## 5. Страница упражнения

При открытии из каталога:

1. Название, группа мышц, оборудование, избранное.
2. Личная заметка.
3. Доступ к памятке «Техника».
4. Последний результат, графики и история.
5. «Используется в тренировках A, C».
6. Редактирование свойств и архивирование.

При открытии из активного занятия приоритет остаётся у прошлого результата и записи подходов, согласно основному ТЗ. Не создавать отдельную копию данных для этого экрана.

## 6. Ручной выбор альтернатив

В панели «Заменить» сначала показывать основное упражнение и уже сохранённые альтернативы. Далее — «Найти в каталоге» и «Подобрать с ИИ».

При ручном поиске предвыбирать группу мышц основного упражнения, разрешать снять фильтр. Показывать оборудование, чтобы быстро найти вариант с доступным инвентарём.

Совпадение группы мышц не означает равноценность упражнений. Не создавать связи альтернатив автоматически.

Выбор действует на текущее занятие; сама альтернатива сохраняется в пункте шаблона. Новое занятие начинается с основного упражнения, как определено в основном ТЗ.

## 7. ИИ-подбор альтернатив

### Запуск

Кнопка «Подобрать с ИИ» открывает короткую форму:

- причина: «Тренажёр занят», «Нет нужного оборудования», «Хочу другой вариант»;
- доступное оборудование — необязательный выбор;
- кнопка «Подобрать» отправляет запрос.

Не выполнять запрос автоматически при открытии панели. Если пользователь не указал оборудование, модель не должна считать его доступность известной.

### Контекст

Передавать исходное упражнение, его оборудование и группу мышц, место в программе, сохранённые альтернативы, причину замены и выбранное доступное оборудование. Передавать компактный список активных упражнений каталога с ID, названиями, группами и оборудованием, без всей истории подходов.

### Ответ

Не более трёх предложений. Каждое содержит:

- название;
- необходимое оборудование;
- короткое объяснение, почему вариант может подойти;
- существенное отличие от исходного упражнения;
- действие добавления.

Сначала предлагать подходящие упражнения из существующего каталога. Если подходящих нет, допускается предложение нового упражнения. Не обещать полную равноценность замены.

Для существующего упражнения — «Добавить и выбрать». Для нового — «Создать и выбрать» с предварительным просмотром названия, группы и оборудования. Пользователь может исправить эти поля до сохранения.

Никаких записей в каталог или программу до явного выбора пользователя. Существующие ID проверять по локальному каталогу; неизвестный ID не использовать как ссылку. Некорректный ответ ИИ не должен менять данные.

После принятия: добавить альтернативу в нужный пункт программы без дубликатов и выбрать её для текущего занятия, если оно активно.

Не переносить вес исходного упражнения на замену. Использовать собственную историю выбранного упражнения; если её нет — пустые поля. Уже записанные подходы других вариантов сохраняются.

Ошибка сети оставляет доступными ручной выбор и сохранённые альтернативы. Результат запроса не нужно постоянно хранить; сохраняются только принятые упражнения и связи.

## 8. Памятка по технике с ИИ

### Создание

В пустом блоке «Техника» — «Создать памятку с ИИ».

Передавать название, уточняющие названия, оборудование и группу мышц. Для неоднозначного упражнения вроде «Тяга» сначала запросить уточнение варианта и оборудования. Не генерировать конкретную инструкцию на основе неясного названия.

Структура памятки:

1. Исходное положение.
2. Выполнение движения.
3. На что обращать внимание.
4. Типичные ошибки.

Общий объём: 5–8 коротких предложений. Без длинных статей, назначения рабочих весов и обещаний безопасности. Не выдавать текст за оценку фактической техники пользователя.

### Просмотр и сохранение

- Сгенерированный текст сначала показывать как черновик с действиями «Сохранить», «Редактировать», «Отмена».
- После сохранения памятка принадлежит упражнению каталога и доступна офлайн.
- Рядом с названием упражнения во время занятия — действие «Техника», открывающее нижнюю панель.
- Не разворачивать всю памятку над формой подходов.
- Видимая пометка «Создано ИИ»; после ручных правок — «Создано ИИ, отредактировано».
- Короткое пояснение: памятка может содержать ошибки и не оценивает фактическую технику пользователя.
- Сохранять источник и дату обновления памятки.

### Обновление

Можно редактировать вручную или запросить новую генерацию. Новый вариант показывать отдельно от сохранённого; заменять только после явного «Заменить памятку». Ошибка или отмена не изменяет прежний текст и ручные правки.

Личную заметку генерация и обновление техники не меняют.

## 9. Архитектурные ограничения

- Использовать существующий ИИ-прокси; API-ключ не переносить в клиент.
- Локальная работа каталога, заметок, истории и сохранённых памяток не зависит от доступности ИИ.
- ИИ предлагает данные, приложение валидирует их и сохраняет только после явного действия пользователя.
- Внешний текст отображать безопасно средствами существующего UI; не вставлять ответ модели как произвольный HTML.
- Сохранить экспорт/импорт JSON, включив новые поля и архивный статус; обеспечить совместимость со старой схемой.
- При ошибке локального сохранения не показывать успех и не терять введённый текст.
- Обновить кеш service worker при добавлении модулей.

## 10. Порядок реализации

1. Каталог: поиск, фильтры, информативные строки и контекстный выбор.
2. Данные: оборудование, избранное, другие названия, личная заметка; создание из поиска и архивирование.
3. Страница упражнения с общей историей и доступом к заметкам.
4. ИИ-подбор альтернатив с проверкой ответа и явным принятием.
5. Генерация, редактирование и офлайн-просмотр памятки по технике.

Не добавлять в этот объём видео, изображения, внешнюю энциклопедию, автоматическое изменение программы, перенос рабочих весов между упражнениями и медицинский подбор замены при боли или травме.

## 11. Ключевые проверки

- Поиск по названию/синониму и комбинации фильтров возвращает корректные результаты без дублей.
- Выбор из каждой точки входа выполняет правильное действие и сохраняет контекст навигации.
- Создание из поиска не требует повторного ввода названия; похожее существующее упражнение видно до сохранения.
- Архивирование не удаляет историю; восстановление возвращает упражнение в выбор.
- ИИ не меняет данные до принятия. Несуществующий ID, некорректный ответ и ошибка сети обрабатываются без потерь.
- Принятие альтернативы не создаёт дубликат и не переносит вес исходного упражнения.
- Генерация техники для неоднозначного названия требует уточнения.
- Повторная генерация и её отмена сохраняют старую памятку и личную заметку.
- Сохранённые техника, заметки и каталог доступны без интернета.
- Старый JSON импортируется без выдуманных новых свойств; экспорт новой версии восстанавливает все добавленные данные.
